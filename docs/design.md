# AI 文档阅读器设计文档

## 1. 项目定位

一款基于 Electron 的桌面 AI 文档阅读器。用户可以在左侧浏览本地文件列表，在中间通过多标签页同时阅读多个 PDF / Word / TXT 文档，在右侧与 AI 进行基于当前文档的问答。支持划词问答、手动全文总结、左右侧边栏折叠、窗口状态记忆，以及打包为独立安装程序。

## 2. 为什么要这么设计

### 2.1 需求背景

用户希望拥有一个类似 Tabbit 的 AI 助手体验，但聚焦于本地文档场景：
- 不需要完整的网页浏览器内核，降低实现复杂度。
- 本地文件内容可控、格式固定，便于提取和构建上下文。
- 文档阅读是 AI 问答的高频场景，落地价值明确。

### 2.2 为什么不直接做 AI 浏览器

真正的浏览器需要处理网页动态渲染、跨域、Cookie、Session、Agent 自动化等复杂问题，对个人工具来说工程量和稳定性都不可控。而文档阅读器只处理本地文件，技术边界清晰，更容易做出可用、稳定的效果。

## 3. 技术架构

### 3.1 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                      Electron 主进程                         │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────┐  │
│  │ 文件解析模块  │  │ LLM 客户端   │  │   上下文存储     │  │
│  │ PDF/Word/TXT │  │ 智谱/DeepSeek│  │ 文档+历史消息    │  │
│  └──────────────┘  └──────────────┘  └──────────────────┘  │
│  ┌────────────────────────────────────────────────────────┐│
│  │ 窗口状态持久化 (electron-store)                         ││
│  └────────────────────────────────────────────────────────┘│
└────────────────────┬────────────────────────────────────────┘
                     │ IPC
┌────────────────────┴────────────────────────────────────────┐
│                      Electron 渲染进程                       │
│  ┌────────────┐  ┌──────────────────────────────┐  ┌──────┐│
│  │ 文件列表    │  │  Tab 栏 + 文档阅读区          │  │ AI   ││
│  │ (可折叠)   │  │  多标签页、划词监听            │  │面板  ││
│  └────────────┘  └──────────────────────────────┘  │可折叠││
│                                                    └──────┘│
└─────────────────────────────────────────────────────────────┘
```

### 3.2 技术选型

| 模块 | 选型 | 理由 |
|------|------|------|
| 桌面框架 | Electron | 成熟、文档丰富、用 HTML/CSS/JS 开发 |
| PDF 解析 | `pdf-parse` | 纯 Node 包，调用简单，适合提取正文 |
| Word 解析 | `word-extractor` | 同时支持 .doc 和 .docx，无需外部程序 |
| TXT 读取 | Node.js `fs` | 无需额外依赖 |
| LLM 协议 | OpenAI 兼容格式 | 智谱、DeepSeek、通义千问均支持，用户可自由切换 |
| 状态持久化 | `electron-store` | Electron 官方推荐，轻量易用 |
| 打包工具 | `electron-builder` | 社区主流，可打包为 exe/installer |
| 测试框架 | Node.js 内置 `assert` + 简单脚本 | 避免引入复杂测试框架 |

## 4. 功能模块

### 4.1 文件管理模块

**职责**：读取本地文件，解析为统一文本格式，供渲染和 AI 上下文使用。

**支持格式**：
- `.pdf`：使用 `pdf-parse` 提取文字。
- `.doc` / `.docx`：使用 `word-extractor` 提取纯文本。
- `.txt` / `.md`：使用 `fs.readFile` 直接读取 UTF-8 内容。

**能做到**：
- 通过系统文件对话框选择文件或文件夹。
- 左侧展示文件列表，点击在标签页中打开文档。
- 将文档内容渲染到中间阅读区。

**做不到**：
- 不支持扫描版 PDF（图片型 PDF）的文字提取，未集成 OCR。
- 复杂 Word 排版（表格、图文混排）会丢失格式，只保留纯文本。

### 4.2 多标签页模块

**职责**：支持同时打开多个文档，每个文档一个标签页。

**实现方式**：
- 中间区域顶部显示 Tab 栏，每个 Tab 显示文件名和关闭按钮。
- 点击 Tab 切换当前显示的文档内容。
- 点击左侧文件列表中的文件：
  - 若该文件已有 Tab，则切换到对应 Tab。
  - 若没有，则新建 Tab 并加载内容。
- 关闭 Tab 时，切换到相邻 Tab；关闭最后一个 Tab 时显示空状态。
- 每个 Tab 拥有独立的 AI 上下文（由文件路径标识）。

**能做到**：
- 同时打开多个文档。
- 在不同文档间快速切换。
- 每个文档保留独立聊天记录。

**做不到**：
- 拖拽排序 Tab。
- 跨文档联合问答。

### 4.3 文档阅读模块

**职责**：在 Tab 内容区展示文档内容，并监听用户划词行为。

**实现方式**：
- 将文档文本按段落渲染为 HTML。
- 监听 `mouseup` 事件获取选中文本。
- 选中文本后弹出"问 AI"浮动按钮，点击后发送到聊天面板。

**能做到**：
- 清晰展示文档正文。
- 划选任意文字并触发问答。

**做不到**：
- 完美还原 PDF/Word 的原生排版样式。
- 支持在文档内做标注、批注、高亮保存。

### 4.4 侧边栏模块

**职责**：提供可折叠的左右侧边栏，优化阅读空间。

**实现方式**：
- 左侧文件列表侧边栏支持一键折叠/展开。
- 右侧 AI 聊天面板支持一键折叠/展开。
- 折叠后边栏收缩为窄条，保留展开按钮。

**能做到**：
- 用户可自由控制界面布局。
- 中间阅读区获得更大空间。

### 4.5 AI 聊天与上下文模块

**职责**：维护基于当前文档的聊天上下文，调用 LLM 回答问题。

**上下文设计**：
- 每个打开的文档（以文件路径为 key）拥有独立的对话历史。
- 每次请求时，将"文档全文"作为 system 上下文，"历史对话 + 当前问题"作为 messages。
- 若文档过长，按 token 预算对文档正文进行尾部截断。

**功能点**：
- 右侧聊天面板展示当前文档的历史消息。
- 用户输入问题，AI 基于当前文档回答。
- 手动触发"总结全文"。
- 划词内容自动填入输入框或作为问题上下文。

**能做到**：
- 基于当前文档的多轮问答。
- 划词后针对选中内容提问。
- 手动总结全文。
- 配置用户自己的 API Key、Base URL、模型名称。

**做不到**：
- 跨文档联合问答。
- 长文档的语义检索/RAG。
- 真正的 Agent 多步推理与工具调用。

### 4.6 窗口状态持久化模块

**职责**：记住窗口大小、位置和最大化状态，下次启动时恢复。

**实现方式**：
- 使用 `electron-store` 保存窗口 bounds。
- 窗口关闭前保存当前状态。
- 应用启动时读取状态并恢复窗口。

**能做到**：
- 记住窗口大小和位置。
- 记住最大化状态。

### 4.7 模型配置模块

**职责**：让用户配置自己的大模型服务。

**支持配置项**：
- API Base URL
- API Key
- 模型名称
- 最大上下文长度

**默认推荐**：
- 智谱 GLM-4-Flash
- DeepSeek-V3
- 通义千问

### 4.8 打包模块

**职责**：将应用打包为 Windows 安装程序。

**实现方式**：
- 使用 `electron-builder`。
- 配置 `package.json` 中的 `build` 字段。
- 提供 `npm run dist` 脚本生成安装包。

**能做到**：
- 生成 `.exe` 安装程序。
- 生成便携版 `.exe`。

**做不到**：
- 自动签名（需要证书）。
- 自动更新（需要服务器）。

## 6. 风险与边界

| 风险 | 说明 | 应对 |
|------|------|------|
| PDF 文字提取失败 | 扫描版或特殊编码 PDF | 明确不支持，给出提示 |
| 文档过长超过模型上下文 | 大文档可能导致请求失败 | 按配置的最大长度截断 |
| 用户未配置 API Key | 无法调用 LLM | 首次启动提示配置 |
| 模型返回不稳定 | 不同模型格式差异 | 采用 OpenAI 兼容格式统一处理 |
| 多标签页内存占用 | 同时打开大文档可能占用较多内存 | 关闭 Tab 释放对应上下文 |
